# PLAN 0171 — Redact the identifiers already in the tree, so pushes pass the disclosure guard

Implements [0171-MADR-redact-published-identifiers-so-pushes-pass-the-disclosure-guard.md](0171-MADR-redact-published-identifiers-so-pushes-pass-the-disclosure-guard.md)
decisions D1–D5, closing findings F1–F5.

## Goal

- The disclosure guard, run read-only against the rebuilt `master`, reports 0 hits, messages
  included. `git push origin master` then succeeds.
- `git diff backup/pre-0171..master` touches only the 61 files, and in them only the redacted
  lines.
- The redacted Go and Dart tests pass, and so does the full Windows suite.
- A dispatched `ci.yml` run is green, including 0170's three new steps. That closes 0170's A4.

## Scope

### In scope (the only files any phase may touch)

- The 61 files the tool's dry run lists (MADR table): 37 records under `docs/spec/`, 15 under
  `docs/kilo-spike-7.4.20/`, `docs/0100-findings-update-refresh.md`,
  `internal/cli/pair_test.go`, `internal/config/config_test.go`,
  `internal/provider/kilo/dialect_test.go`, the three Dart tests, and the two wire `meta.json`
  files.
- The records whose commit-hash citations change in the rebuild: the 0169 and 0170 pairs, and
  this pair.
- Git refs: a new `backup/pre-0171` branch at today's `master`, a working branch
  `rebuild-0171`, and `master` moved to its tip.

### Out of scope

- **`origin`'s existing history.** It already holds these identifiers. Rewriting published
  history is the owner's decision alone, and it is not taken here.
- **The guard and its deny list**, which belong to the owner's dotfiles (MADR D5 only reports
  their defects).

## Stability rule

Each phase ends with its own verification below. Commits use `git commit --no-edit`. Nothing is
pushed before P4's guard check is clean, and the push itself needs the owner's go-ahead in the
same turn.

## Cross-cutting contracts

- **C1 — Nothing is lost.** `backup/pre-0171` points at today's `master` before anything moves,
  and is deleted only after the push lands.
- **C2 — No message is written by hand.** Every commit, the replays included, takes the hook's
  message. A message the guard flags is regenerated by re-committing through the hook.
- **C3 — Tests keep their meaning.** Test inputs get neutral valid values, never `<…>`
  placeholders.
- **C4 — The guard is never bypassed.** No `--no-verify`, and no change to the deny list.

C2 is the one most at risk. If a regenerated message keeps echoing an identifier, writing one
by hand looks like the quick fix, and it is forbidden.

## Dependency and delivery order

P1 → P2 → P3 → P4 → P5, strictly. P1 starts from a clean working tree.

## Implementation Steps

### P1 — Backup and the redaction commit (D1; closes F1, F3)

1. Create `backup/pre-0171` at `master`, then `git switch -c rebuild-0171 origin/master`.
2. Run `PYTHONIOENCODING=utf-8 github-disclosure.py redact --apply` on the 53 prose and
   evidence files. The tool edits every file it lists, so the 8 test and fixture files are
   first restored to their original bytes and then edited by a reviewed script:
   - the relay host ID becomes `mac-host` in the 3 Dart tests and 2 Go tests;
   - the captured directory in `dialect_test.go` becomes `/Users/user/…`;
   - the two `meta.json` notes keep the tool's placeholder.

   Every edit asserts its anchor count, and writes bytes, not text.
3. Verify:
   - the dry run now says "would edit 0 file(s)";
   - `go test ./internal/cli ./internal/config ./internal/provider/kilo` passes;
   - the three Dart tests pass;
   - gofmt and golint are clean on the 3 Go files.
4. Commit with `git commit --no-edit`.

### P2 — Rebuild the unpushed commits (D2; closes F2)

1. For each commit in `origin/master..backup/pre-0171`, oldest first:
   `git cherry-pick --no-commit <sha>`, then `git commit --no-edit`.
2. A conflict stops the loop. It is reported, not resolved by guesswork.

### P3 — Tree equality and hash citations (D3)

1. `git diff backup/pre-0171 rebuild-0171` must list only the 61 files. A script checks that
   every changed line is a deny-list match replaced by its placeholder, or by the P1 neutral
   value.
2. Update the commit-hash citations in the 0169, 0170 and 0171 records to the rebuilt hashes,
   with an old-to-new map in PLAN 0171's execution record. Commit.

### P4 — Guard clean, then publish (D4; closes F4, F5)

1. Run the guard read-only with the ref line for `rebuild-0171` → `origin/master`. It must
   report 0 hits.
2. If a message is flagged, regenerate it with `git reset --soft HEAD~1` and
   `git commit --no-edit`. That is safe only for the top commit; a deeper one means re-running
   P2 from that point.
3. Move `master` to `rebuild-0171` (`git branch -f master rebuild-0171` after switching away,
   then switch back).
4. On the owner's go-ahead: `git push origin master`.

### P5 — CI and close-out (0170 A4)

1. Dispatch `ci.yml` on `master`. All jobs green, and the three new steps visible in the `go`
   job's log.
2. Delete `backup/pre-0171` and `rebuild-0171`, and record the execution.
3. Report the tool's two defects (MADR D5) to the owner.

| A5 | A dispatched `ci.yml` run is green, including 0170's new steps | D4, 0170 D3 |

The criterion most likely to be dropped quietly is **A3**. Once the guard says 0 and the push
works, checking that nothing *else* changed in twelve replays feels redundant. It is the only
evidence that the rebuild changed nothing it should not have.

## Rollout and Rollback

Until P4 step 3, `master` has not moved and the backup exists, so rollback is deleting
`rebuild-0171`. After P4 step 3 and before the push: `git branch -f master backup/pre-0171`.
After the push, the redaction is public, which is the point of it. Nothing needs rolling back.

## Deferred (named, so they are not mistaken for oversights)

- **Rewriting `origin`'s history** to remove identifiers already published. That is the
  owner's decision; a force-push rewrites every hash, and forks and clones keep the old ones
  regardless.
- **Fixing the tool's two defects.** They belong to the dotfiles repository and its own
  records.
