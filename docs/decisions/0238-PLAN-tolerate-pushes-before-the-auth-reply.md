# Implement tolerating server pushes that arrive before the auth reply

Associated MADR: [0238-MADR-tolerate-pushes-before-the-auth-reply.md](0238-MADR-tolerate-pushes-before-the-auth-reply.md)

## Goal

When this plan is done:

* `authV2` in `internal/ws/resume_test.go` reads until the `auth_ok`, skipping pushes (D1), so
  `TestResumeReturnsOwnedSessionBounds` no longer fails when an event lands before the reply.
* `docs/guides/protocol-v1.md` says that a push can arrive before the auth reply, and how to match
  the reply (D2).
* The daemon is unchanged (D3).

## Scope

* **P1, one commit:**
  * `internal/ws/resume_test.go`: `authV2` only.
  * `docs/guides/protocol-v1.md`: one paragraph in the Authentication section.
  * This PLAN's execution record, and the MADR if a deviation changes a decision or a fact.
* **Records commit, before P1:** this pair, and the records table in `docs/README.md` regenerated by
  `scripts/check_records.py --write-index`, plus one hand-written "I want to…" row.
* **Out of scope:**
  * `internal/ws/server.go` and every other daemon file (D3).
  * `docs/guides/protocol-v2.md`: its `auth_ok` additions build on v1's section.
  * The phone and `scripts/smoke-protocol`, which already match replies by `id` (F4).
  * Other `internal/ws` tests. The sweep (F7) found no other test that reads an auth reply after a
    session exists.

## Constraints

* The agent stages on `master`; the owner commits and pushes.
* No commit carries a hostname, account name, or real-machine path. The disclosure guard preview
  (`python3 ~/.global-git-hooks/github-disclosure.py redact`) runs before staging.
* Experiments run in a scratch clone in the session scratchpad. The working tree is never used to
  inject delays.
* Shell commands are single commands; anything with a loop or a condition is a Python script in the
  scratchpad.

## Implementation Steps

### P1 — The test helper and the guide (D1, D2)

1. **`git status` is clean** apart from this plan's own files, and `master` equals `origin/master`.
2. **Change `authV2`** (`internal/ws/resume_test.go:63-81`). Replace the bare read and its type
   check:

   ```go
   	writeEnv(ctx, t, conn, env)
   	got := readEnv(ctx, t, conn)
   	if got.Type != protocol.TypeAuthOK {
   		t.Fatalf("want auth_ok got %s %s", got.Type, string(got.Payload))
   	}
   ```

   with a read that skips pushes:

   ```go
   	writeEnv(ctx, t, conn, env)
   	// A push can be queued before the auth reply (0238-MADR F1): read past
   	// events to the reply. readUntil still fails on any other type, so an
   	// auth_error stops the test with its payload.
   	got := readUntil(ctx, t, conn, protocol.TypeAuthOK)
   ```

   The rest of `authV2`, and every test that calls it, is unchanged.
3. **Add the guide paragraph** to `docs/guides/protocol-v1.md`, section Authentication, after the
   paragraph on `Authorization: Bearer` and before "Unauthenticated clients may only use…":

   ```markdown
   **Frame order.** The daemon treats the socket as authenticated as soon as it accepts the token
   or pair code, a moment before it queues the `auth_ok` or `pair_ok` that answers the request. A
   server push, such as an `event` or `providers.prewarm`, can therefore arrive before that reply.
   Match the reply to your request by `id`, and handle a push that arrives first exactly as you
   would one that arrives after
   ([0238-MADR-tolerate-pushes-before-the-auth-reply.md](../decisions/0238-MADR-tolerate-pushes-before-the-auth-reply.md)).
   The `auth_ok` or `auth_error` sent after a Bearer upgrade has no `id`; match it by `type`.
   ```

   The guide elsewhere cites records as "MADR NNNN". This paragraph links the full filename instead,
   as `AGENTS.md` requires.
4. **Seen to fail, then to pass.** The scratchpad's `flake_widen.py` gains a mode that copies the
   working tree's `internal/ws/resume_test.go` into its scratch clone. Two runs, each with a 30 ms
   delay inside `handleAuth`'s resume branch and a 10 ms delay before the pump's re-advertise
   (MADR F3), `-count=50`:
   * the committed `resume_test.go`: expect 50 of 50 failures with
     `resume_test.go:153: want auth_ok got event`;
   * the changed `resume_test.go`: expect 50 of 50 passes.

   The clone is removed after each run and checked gone.
5. **Gates, on this Mac:**
   * `make pre-add-check FILES="internal/ws/resume_test.go"`;
   * `go test -race -count=1 ./internal/ws`;
   * `make race`;
   * `make check-records`;
   * the disclosure guard preview.
6. **Stage** for the owner's commit: `internal/ws/resume_test.go`, `docs/guides/protocol-v1.md`,
   this PLAN with its execution record, and the MADR if it was amended. Set this PLAN's `status`
   to `complete` once CI on the push passes.

### The sweep's limits

`sweep_auth_order.py` (MADR F7) matches text. It finds a test that creates a session through
`TypeSessionCreate` or a manager `Create` call, and later reads an auth reply directly or through a
helper whose body names `TypeAuthOK` or `TypePairOK`. It would miss a session created another way,
such as a helper that hides the create, and a handshake read without naming either type. It is a
pointer for review, not a gate, so it is not committed.
